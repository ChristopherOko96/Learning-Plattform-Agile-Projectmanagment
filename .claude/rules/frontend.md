# Frontend Rules

- Entwickle das User Interface als eigenständige Aufgabe.
- Verwende Komponenten, wiederverwendbare Layout-Bausteine und Platzhalterdaten für spätere Inhalte.
- Das Frontend sollte zuerst einen stabilen Ablauf bieten:
  - Startseite / Dashboard
  - Rollen-Auswahl
  - Szenario-Ansicht
  - Feedback-Bereich
- Kommuniziere API-Schnittstellen klar: welche Felder erwartet werden.
- Keine echten Inhalte einpflegen, solange die Struktur noch nicht steht.
- Priorisiere responsives Design und mobile Darstellung.
- Prüfe CSS auf Konsistenz und vermeide doppelte Regeln.

## Plugin Designer

- Nutze den **design:ux-copy**-Skill bei UI-Text, Buttons, Fehlermeldungen und CTAs.
- Nutze den **design:design-critique**-Skill nach der Implementierung einer neuen Seite oder Komponente, um Usability und Konsistenz zu prüfen.
- Nutze den **design:accessibility-review**-Skill bei neuen Formularen, Dialogen oder interaktiven Elementen (WCAG 2.1 AA).
- Nutze den **design:design-handoff**-Skill, wenn eine Komponente fertig ist und ein Dev-Spec benötigt wird.
- Nutze den **design:design-system**-Skill, wenn neue Komponenten auf Konsistenz mit dem bestehenden Design-System geprüft werden sollen.
- Die Design-Skills sind **bedarfsgesteuert**: nur einsetzen, wenn eine Designentscheidung getroffen, überprüft oder dokumentiert werden muss.
